| 0005 explainable baselines, no trained model | Four `DemandPredictor` strategies are registered in `src/container.ts`. The median strategy was added without changing `DemandService`, the API or the UI (QA-7 exercised). Synthetic data is labelled in the database (`source`), the API (`dataSources`) and the office UI banners. `npm run evaluate` reproduces MAE 1.45 / 1.44 / 1.42 / 1.98. | **Gradient boosting or a neural model:** with only synthetic data it would learn the generator, not the campus, and its accuracy would be meaningless. **No forecasting at all:** loses the office use case (UC5). The median and the weighted mean trade lower MAE against more negative bias; neither result says anything about reality. | At least one semester of real waiting requests: rerun the backtest on real data only, and consider a trained model only if it beats the seasonal baseline on held-out real weeks. |
| 0006 signed HttpOnly cookies and edge role checks | Passwords are scrypt hashes. Sign-in locks after 5 failed attempts for 5 minutes (`src/config.ts`). The body limit is 64 KB (`src/web/app.ts`). Session expiry closes open SSE streams (integration and browser tests). | **JWT in localStorage:** readable by injected scripts, and EventSource cannot send it. **Server-side session table:** allows real revocation, at the cost of a lookup per request; this is the main gap of the current choice. **University SSO (OIDC):** right for production, not available for a local prototype. | Any deployment beyond a local demonstration: add revocation or SSO, set `SECURE_COOKIES` behind HTTPS, and remove the public demo passwords. |
| 0007 offline schematic SVG map | The map is drawn from route geometry with a 100 m grid (`public/js/map.js`), with no third-party tile requests (the CSP blocks them).
